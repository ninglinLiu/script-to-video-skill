# 共用生产接口，按项目选择表达

固定的是证据范围、资产身份、真实语音时间线、镜头状态、可回退修改与交付接口。风格、文章类型、长度和剪辑可以变化。所有组合尚未验证，配置清单不是万能渲染调度器。

## 开始时只做一次选择

优先继承用户已经认可的工程和视觉锚点，在当前项目保存下面这些选择及理由；已有brief可直接补充，不新建一堆重复配置。

| 维度 | 可选方向 | 选择依据与边界 |
|---|---|---|
| 内容组织 | 概念机制、事件复盘、证据论证、故事类比 | 看观众的问题与证据；不是每篇都必须套“冲突→三点→金句” |
| 视觉 | 当前认可风格，或目录中的暖纸、暗金、像素、网点等 | 检索一个候选配方和对应源码；新风格先做连续片段，不重搭运行时 |
| 时长/画幅 | 60–90秒竖屏、约三分钟、90–150秒横屏章节、自定义长片 | 由任务决定；短片选一个主要机制，长片增加章节论证而非加慢镜头 |
| 剪辑 | 对象连续、证据硬切、分屏比较、路径跟随、混合资料剪辑 | 对应解释任务；统一字体/颜色/素材处理，允许不同构图 |
| 资产策略 | 复用已有、加工已有、按缺口新增 | 数值与公式由代码驱动，复杂人物和质感可使用现有或生成图 |
| 工具与模型 | 当前可靠渲染器、主创模型、视觉审查、可用图像/TTS工具 | 强模型统筹，工具能力分别核实；不要假定一个模型自带所有服务 |

最小配置示意：`contentForm`、`styleRef`、`durationSeconds`、`aspect`、`editGrammar`、`engineProject`、`assetReuse`、`modelAndTools`。这些是制作决策字段，不是现有渲染器已经消费的统一API。

## 选好之后如何变化

同一条片保持角色与信息语义稳定。故事确实需要对照画风、资料段或章节切换时，设计其目的、进入/退出和继承对象；不把“统一”误解成每镜相同布局，也不随意混搭所有参考。

例如，数字机制可以在同一账单上改变分母；事件复盘可以把文献硬切到地图，再让同一路径进入机制图；像素故事可以由角色道具接住后续数据。它们共享证据和时码接口，但不强求同一套镜头。

先复用现有源码、字体、角色、材质与音轨。用户要求改变风格时才建立新的视觉基线；仅修字幕、节奏或衔接时不要连画风、角色和工程一起重做。新组合优先验证最有风险的8–13秒，再扩展。

## 多模态能力与图像生成分开

看图、生成图、执行渲染、合成语音是不同能力。主创模型可以通过harness调用图像工具和TTS；它不必原生输出位图。多数现有机制动画可用源码、字体和资产重渲，换文章不意味着必须重新生成全部图片。

对 DeepSeek 或其它模型，检查当前宿主实际提供的读图、终端、文件和语音工具，不从模型名称推断能力。`poisson-cinema` 已带两张生产图和字体，复用该分支无需重新生成位图；视觉审看仍需宿主能把真实帧提供给模型。不能读图时可验证编码与数据，但不能声称审美已通过。

正式制作沿用用户指定的高能力主创模型，不以适配普通模型为质量上限。记录精确模型与工具版本；如果当前宿主不能看图、不能调用指定图像工具或缺少TTS，说明具体能力缺口，复用能用的资产，不虚构服务。
