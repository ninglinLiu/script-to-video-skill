# 是什么 Skill、还缺什么、换模型怎样运行

核对日期：2026-10-24。代码核对基线：`e098ef47bf0deb5baefcc6563822d60745b7bab9`。本次是代码、文件和任务要求审查，没有运行 DeepSeek，也没有在全新机器上完成验收。

## 结论

这是一个有效的 **Agent 工作流 Skill**：根目录有带名称、描述的 `SKILL.md`，配套指令、脚本、资源和案例。它不是独立的视频应用，也不是已经验证“任意模型、任意文章一次成片”的服务。

原任务的方向可按现有路线继续实现，但**当前仓库尚未完整满足任务验收**。已有片、组件和工程是可复用基础；选题、论证、分镜、部分场景代码与画面审查仍依赖执行任务的 Agent。

开放 Skill 格式让工作流可以被不同 Agent 读取，不保证不同模型具备相同创作能力，也不自动安装工具、提供账号、生成事实证据或赋予视觉理解能力。

## 对照原任务

本次在线任务文档跳转到登录页，因此依据用户此前提供的《任务清单.md》以及项目保存的任务要求核对；不声称已重新读取当前在线版本。原任务文件与账户访问资料不随公开仓库附带。

原任务要求一个入口、固定风格、自动完成并自检；三篇稿件中两篇开发，一篇最终验收。交付包含60–90秒竖屏短片、8–10分钟横屏长片、对齐字幕、可编辑工程、素材清单、成本效率记录。最终还要完整观看同文短长片、抽查数字、修改一句旁白后检查重对齐，并明确处理配音或素材失败。

| 要求 | 仓库已有证据 | 当前判断 |
|---|---|---|
| 一个入口，输入文稿 | Skill作为Agent入口；分散的配音、渲染和审查命令 | 没有统一的任意文章生产命令；依赖Agent选择并改造具体工程 |
| 固定品牌风格 | `assets/style-lock.json`、规范和多个风格库 | 可以锁定方向；配置尚未成为所有工程统一强制执行的主题接口 |
| 60–90秒短片 | 历史成片与组件案例 | 有制作经验；不是同一冻结流水线的跨文章验收证明 |
| 8–10分钟横屏长片 | 长片流程文档、105.57秒完整章节 | 尚未完成该时长和持续观看质量的验证；三分钟片也不替代此项 |
| 真实配音与SRT | Edge TTS、WordBoundary、配音缓存及字幕 | 章节实现可复用；换语音服务需要适配，整套新文章重对齐仍须验证 |
| 可编辑工程 | Remotion源码、分段素材、FCP7交换XML | 用户已手动验证既有剪映/PR流程，按要求不重复；XML不冒充原生草稿，单个动画对象仍在源码编辑 |
| 素材来源 | 来源、许可、逐文件哈希与使用范围 | 有基础；每条新片仍需建立其实际用材清单 |
| 耗时、成本和人工介入 | 规范与部分制作记录 | 尚无覆盖整项验收、统一自动采集的完整报告 |
| 修改一句旁白及异常处理 | 稿件哈希、时间戳、部分明确报错 | 有局部机制；不是旁白修改、场景重绑定、失败恢复全部通过的验收记录 |
| 两篇开发、一篇最终验收 | 多次历史探索与用户反馈 | 没有固定版本在该协议下完成整体验收的证据 |

技术通过、制作方画面审查、用户观看认可分别记录，不把其中一个当作另两个。

## 模型、Agent、harness、Skill分别做什么

此处的 harness 指承载模型执行任务的程序，中文可理解为执行框架。Agent通常是“模型在这个框架里持续读写、调用工具、观察结果并继续行动”的工作方式，不需要把Agent和harness误解成两个额外智能模型。

| 层 | 职责 | 是否由本仓库提供 |
|---|---|---|
| 模型 | 理解原文、权衡论证、编写分镜与代码、发现问题 | 否；接入所选模型API或本地推理服务 |
| Agent/harness | 加载Skill、维护上下文、实际执行工具、管理长任务和重试 | 否；使用兼容宿主并验证其工具适配 |
| 本Skill完整目录 | 制作流程、规范、脚本、字体/素材与可运行案例 | 是；只复制`SKILL.md`会丢失依赖资源 |
| 渲染运行环境 | Node、Python、Chrome、FFmpeg等实际生成文件 | 不随Skill完整打包；需要安装或环境预置 |
| 输入和外部服务 | 正文、证据、品牌选择、配音；按需补充图像/资料 | 部分示例已有；新文章和服务访问需另备 |

把文本粘到普通聊天窗口里，不会使模型获得本地执行能力。API“支持工具调用”指模型能请求调用；真正读取文件、运行FFmpeg和返回画面的仍是harness。

## 本地必须准备什么

以下按现有Remotion章节路线说明，不表示所有历史工程都有相同依赖。

| 材料或依赖 | 已经包含什么 | 新环境要准备什么 |
|---|---|---|
| 完整仓库 | Skill、参考规则、脚本、案例、所列开源素材及许可 | 完整克隆并固定提交；不要只下载入口文档 |
| Node/npm | 章节`package.json`和锁文件 | Node.js 22+、npm；在`examples/chapter-01/工程`执行`npm ci` |
| Python | Python脚本、章节`requirements.txt` | Python 3.11+；改配音时安装章节要求的依赖，目前固定`edge-tts==7.3.1` |
| 浏览器渲染 | Remotion渲染配置 | Remotion管理的Chrome Headless Shell，或用`REMOTION_BROWSER`指定兼容浏览器 |
| 编解码 | FFmpeg调用方式 | `ffmpeg`和`ffprobe`可从PATH调用 |
| 字体与图片 | 章节所用字体、许可和已公开画面素材 | 新选风格逐项核对；一个示例有字体不等于全部历史工程的字体齐备 |
| 配音 | 现成章节MP3/WAV及WordBoundary | 新稿需联网语音服务；现有Edge TTS路径不是离线能力或商业SLA保证 |
| 模型访问 | 不含账户、密钥或模型权重 | 自己的模型端点、凭据和使用额度，或另行部署本地推理 |
| 证据与正文 | 案例改编稿、有限引用和来源记录 | 完整新文章、出处、必要的一手证据；登录平台需授权访问或提供正文 |
| 品牌约束 | 默认风格配置和可选素材库 | 确定一个主风格、音色、字幕及输出规格；资料多不代表可以随机混用 |
| 音乐及其他资产 | 公开版旁白和可分发资源 | 使用指定外部音乐时自行提供可用文件及使用范围；不混入仅限本地的素材 |
| 输出工程 | 源码及交换时间线导出脚本 | 按目标编辑器重新生成本机媒体路径；不能沿用另一台机器绝对路径 |

运行远程模型并以CPU进行浏览器渲染，并不天然要求购买本地GPU。内存、磁盘和耗时取决于分辨率、并发与素材；本仓库没有做最低硬件配置基准，不给出未经测试的保底数字。如果改为本地部署模型，模型权重和推理硬件是另一套要求。

首次安装Node依赖、浏览器及新稿TTS需要相应网络访问。运行环境和字体已经齐备后，重渲既有章节不需要再次请求模型或配音服务。全离线的新文章生产尚未验证；需另接本地模型、配音和证据材料。

## Agent/harness必须具备的能力

- 读取目录并按需加载Skill的引用文件，不能仅依赖当前聊天历史里口头传递的参数。
- 写文件、执行Node/Python/FFmpeg命令、观察退出码，等待长渲染任务并读取日志。
- 保留任务状态与文件位置，在上下文压缩或中途恢复后继续。
- 渲染或截取真实画面，把静帧和连续关键帧交给具有视觉能力的审查者；只读日志不足以发现构图与动作问题。
- 在允许范围内取证、调用配音服务，明确报告访问失败；有完整本地资料时不强制联网搜索。
- 对失败进行有限修复，无法满足时报告具体缺口，不能用一份填写为“通过”的JSON替代实际审查。

若执行模型没有图像理解能力，可接独立视觉审查模型或由人复核；后一种配置不能宣称“全自动审美验收”。任何视觉模型的自评也只是内部筛查，是否达到约定观看标准仍需要在验收样本上证明。

## 为什么现在不能只换文章就保证成功

这里有可检查的代码证据，而不只是抽象担忧：

1. [`Chapter.tsx`](../examples/chapter-01/工程/src/Chapter.tsx)中有具体的买入价、现价、损失与回本计算，七段对象状态及基于章节/句子序号的动作。替换文章可能令这些数字、结论或句子索引失效。
2. [`render.mjs`](../examples/chapter-01/工程/render.mjs)渲染已有composition和`timing.json`，支持样片、全片及片段。它不接收任意文章并自动创作画面。
3. [`voice.py`](../examples/chapter-01/voice.py)需要已审过的稿件和结构化脚本，再根据真实语音边界生成时间线。它能帮忙重建时间，不会自动重新设计变化了的论证或镜头。
4. [`audit_episode.py`](../scripts/audit_episode.py)能检查编码、时间区间、文件与记录，但不独立判定事实真伪、字幕烧录内容或观看价值。具体边界见[输入协议](episode-contract.md)。

所以现阶段模型除了“照流程操作”，还承担实质性的内容和工程工作。模型能力变弱时，这些环节可能更容易出错；没有实际比较，不能量化差距或保证强模型能一次完美。

## 换成DeepSeek或其他模型会怎样

“普通DeepSeek”不是一个可复验配置。应记录确切模型ID/版本、思考设置、上下文设置、harness版本和工具集合。品牌名、参数量或“最强”标签不能替代这个记录。

DeepSeek官方提供工具调用接口，普通非思考模式也有调用示例。因此它在架构上可以参与这类Agent流程；这不是本Skill已经在DeepSeek上成功运行的证明。具体API是否支持所需视觉输入、工具协议和上下文行为，应按实际型号和接口核对，而不是假定所有DeepSeek型号相同。

| 场景 | 可以合理判断什么 | 当前不能保证什么 |
|---|---|---|
| 同机器、同源码素材，重渲旧片 | 工作主要由固定工具执行，可不用模型重新创作 | 跨浏览器/操作系统的逐像素一致性未经基准验证 |
| 同机器、换模型、制作新文章 | 环境复用减少安装问题；有工具能力的模型可以尝试 | 论证深度、代码准确、节奏、连续性与原模型同等 |
| 新机器、同模型 | 按依赖和路径配置后应具备制作条件 | 未做干净环境验收，不能说克隆后无需配置 |
| 新机器、普通DeepSeek | 工具协议适配后具备尝试的技术路径 | 单次成功、成本更低、无需人工或长片达标，均未实测 |
| 无工具的普通聊天模式 | 可以协助整理内容和编写脚本 | 不能仅凭Skill自动在本地渲染、读回结果并交付文件 |

若目标是“一个Skill加上具备工具的Agent/harness就能开始”，可以把所需内容和工具接口封装在一个Skill目录中，不必要求用户分别学习十几个Skill。但模型服务、渲染运行时、语音服务、原文与证据仍需可用。**一个入口不等于一个Markdown文件包办所有依赖。**

## 怎样补齐，才能向任务方报告完成

下面是待完成的工程与验收方案，不是本次已经实施的功能。

1. **固定生产接口。** 提供统一任务配置和入口，明确文章、证据、品牌、输出规格；分离脚本、语音时间线、镜头状态和渲染。将当前写死的内容参数改为可校验数据，允许不适合现有组件时明确返回需要的新场景，不能硬套。
2. **固定环境。** 建立依赖和服务检查，报告字体、浏览器、FFmpeg、TTS与凭据缺项；用一份小型样例验证安装。桌面路径配置与公共规则分离；所有必要规则进入仓库，不能偷偷依赖旧聊天或私有目录。
3. **按原任务开发与验收。** 两篇开发稿用于修复，随后冻结代码、风格、模型和harness；第三篇未参与调试的稿件从新会话运行，交齐同文短长片及其余材料，完整观看并抽查事实。允许Agent内部修复，但记录次数、耗时和改动原因。
4. **验证修改和失败。** 修改一句旁白后重新生成声音、字幕、时长和相关镜头，检查实际成片；让素材缺失或配音请求失败，确认清楚报错且不留下“成功”交付。编辑器沿用用户已确认的流程，不重复要求验证已确认项目。
5. **最后换模型。** 保持文章、资产、任务规格与工具一致，换精确记录的DeepSeek配置，在新会话中完成同一协议。可另做原样配置与按该模型适配后的两组运行，分别报告；不能把适配后的结果描述成完全零配置。记录成片问题、事实错误、退出/恢复、人工介入、实际API成本及墙钟时间。

通过这套验收后，应使用有限且可复现的结论，例如：“版本X，在环境Y、模型Z下，完成规定三篇稿件与修改测试，支持约定风格的短片和长片。”在此之前，准确的状态是“可复用的Agent制作Skill及案例，通用生产与跨模型验证仍在开发”。
