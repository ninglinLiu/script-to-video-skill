# 从完整章节扩展长片

目前有约106秒的横屏章节案例和三分钟制作经验；尚未证明8–10分钟的持续观看质量，也未证明跨新文章稳定成功。不得把组件数量、帧数、语速或自动评分当作这两项证明。

## 内容先形成论证

五步产物：原文与证据位置 → 候选问题及取舍 → 口播稿、事实核对、原创算例标记 → 带时间的对象状态分镜 → 使用最终素材的连续样片及完整章节。案例见 `examples/chapter-01/plans/five-steps.json`。

每章写下：观众带着什么问题进入；新增哪条事实、比较或机制；它改变了哪个判断；有什么反例；章末还剩什么问题。删掉没有新增信息的口播和画面重复。不能靠提高TTS语速解决概念堆叠、空泛三点论或观众早已猜到答案的问题。

本例结构：两人买价不同的冲突 → 同一未来路径 → 回本百分比的分母 → 真实账户研究 → 决策理由更新 → 成本仍有用途的反例 → 返回开头。100/40/60为原创假设，研究账户数据另列出处；处置效应的行为事实不等于证明锚定是唯一原因。

## 章节、镜头与对象是三层

全片先形成章节论证，再在章节里安排镜头；短动画组件只实现镜头中的解释动作。每个镜头至少记录：

| 字段 | 需要写出的内容 |
|---|---|
| question / informationGain | 本镜回答什么，新增信息如何推进判断 |
| sourceIds / materialRole | 证据、假设、机制示意还是情绪铺垫 |
| objectId / before / after | 上一镜留下哪个对象；状态怎样改变 |
| entry / exit / nextObject | 注意力位置、运动方向、下一镜接什么 |
| cueRange / start / end | 实际语音时间与解释动作区间 |
| numericInvariant | 单位、分母、比例、价格坐标的约束 |
| verificationTime | 在真实编码的哪些时间点检查 |

案例 `plans/chapter.json` 用同一receipt-A/B与price-60跨段保留身份。它们后退、进入价格标尺、翻面接收证据、再返回；不能简单地给每个组件各加一段入场动画。资料镜头可有目的地硬切，保留问题和因果关系，不强求所有镜头无缝变形。

## 素材承担不同工作

统一字体、调色、证据标注与字幕位置；允许全幅资料、实拍、细节特写、双人比较、机制动画等不同构图。不要把全部段落变成“大标题＋中央动画＋底部解释”。本例仍以动画和论文题头为主，素材类型的长片覆盖尚不充分，不能称为已经解决。

`examples/chapter-01/provenance.json` 记录实际资产。长片新增素材继续登记真实来源、阅读/观看范围、可发布范围、裁切和加工。敏感或用户要求仅本地的材料不得进入共享库、远程模型、GitHub或报告附件；只复用不含敏感内容的方法。

## 生产顺序与局部修改

1. 事实审查绑定口播稿SHA256，完成后生成或复用真实WordBoundary时间线。字幕与动作共用它。
2. 先渲8–13秒，包含解释动作与一个跨镜衔接；本例证明片跨第一、第二段。
3. 做完整低分辨率粗剪，再做成片。检查章内推进与章节交接，不仅审开头。
4. 用全局帧号渲单段，保持前后对象状态；`node render.mjs segment recovery`只重渲选定区间。若文稿改动导致时长改变，下游时间线和字幕须一起更新，不能拼接旧时码。
5. 分开保存干净画面、配音、BGM、字幕和交接记录。配乐变更使用视频码流复制，不重渲画面；实际视频码流哈希比对后才能沿用画面审查。

## 怎样判定进步

逐项记录时间码、观察到的问题、修改前后差异。当前案例实际修复了标题重叠、账单遮挡标题、曲线压说明、价格注释被误读为坐标四项问题；最终32个时间点抽样及3帧颜色转换复核有明确范围，不是整片观看或用户审美认可。

长片扩展需再验证：全片论证是否递进；章节之间问题是否承接；证据与素材是否匹配；音画是否长期单调；局部改动是否保持一致。先做完整章节及可扩展工程是当前用户选择，不自动拉长至8–10分钟。用户已验证的剪映／PR工作流无需重复验证；交付文件的实际Agent观察与用户确认分别保留。
