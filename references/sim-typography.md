# 代码模拟 · 暗金排版（临界点风格）

把一个藏在数据里的数，用代码真的算出来，再一步一步演给观众看。没有旁白，靠逐字打出的大字、实时跑的模拟和背景音乐推进。

**状态：** 2026-11-09 用户说老板（凯撒）喜欢参考片《临界点：渗流理论》，要按这个标准做凯撒公众号的样片。[凯利公式样片](../examples/caesar-kelly/README.md)是按这份文档做的第一条，**制作方自查，用户和老板都还没看**。这是和 [3D 微缩](diorama-3d.md) 并列的一种风格，不替代它。

适合：一个关键阈值、概率、比例或统计规律，能用模拟“算出来”的题目，比如临界点、复利、下注比例、幸存者偏差、均值和中位数的差别。不适合：事件经过、人物故事、需要具体场景的机制，这些用 3D 微缩更好。

## 手法

- **逐字打出**：每秒约 18–20 个字，每个字 0.14 秒内淡入。关键数字和词用金色。一屏最多两行，约 3–4 秒换一屏。
- **大数字揭晓**：先出一层很淡的描边，一道竖直光条从左扫到右（约 1 秒），扫过的地方点亮成金色渐变并发光，光条停在右边再淡掉。全片只给最重要的两三个数用。
- **模拟要真跑**：格子、曲线、计数器都来自同一份算好的数据，画面上的数和文字里的数是同一个变量。参考片的格子是真的渗流模拟，蔓延的前沿是真的广度优先搜索。
- **一档一档试**：同一个模拟换参数重放（30% → 50% → 58% → 60%），旧结果变成灰线留着，新结果金色。观众自己看出拐点在哪。
- **重做一万遍**：从一次运气扩到大量重复，计数器从 0 跑到 10,000，单次的结果变成一条曲线或一片格子。
- **有个真实锚点**：一个历史年份或真实实验（参考片是 1957 年 Broadbent 和 Hammersley），小字注明出处。
- **落到人身上**：最后把数字讲成一句话，再给三条勾选清单、一句“致所有……的人”、片名卡。
- **转场**：整屏淡出再淡入，不硬切，不推拉镜头。画面元素自己生长。

## 结构模板（按参考片的节奏）

| 段 | 时长 | 做什么 |
|---|---|---|
| 钩子 | 6–8 秒 | 两个看起来一样、结果天差地别的对照 |
| 揭晓 | 6–8 秒 | “差别只在一个数：”＋大数字 |
| 规则 | 8–12 秒 | 用最小的模型说清楚规则，格子或硬币 |
| 一档一档试 | 15–25 秒 | 同一模拟换参数重放，旧结果留灰线 |
| 汇总 | 6–10 秒 | 把各档结果连成一条曲线，标出拐点 |
| 重做一万遍 | 10–16 秒 | 大量重复，计数器、分布或格子 |
| 真实锚点 | 6–9 秒 | 历史或实验，注明出处 |
| 落到人身上 | 10–15 秒 | 一句话结论，可引原文观点 |
| 清单、致辞、片名 | 12–16 秒 | 三条勾选、“致所有……”、片名卡 |

参考片 160 秒，凯利样片 122 秒。短于 90 秒时，先砍“汇总”和“真实锚点”，不要砍“一档一档试”。

## 怎么做

```sh
python scripts/simfilm.py doctor                        # 查 node、ffmpeg、字体、playwright
python scripts/simfilm.py new --episode ./ep            # 起工程；加 --source caesar-kelly 从样片改
cd ep
python data/build_data.py                               # 算出所有数字 → web/data.json、qa/data-summary.json
node render.mjs stills 3.5,10,30,60 --dir s1            # 静帧观感测试
python ../scripts/simfilm.py sheet qa/s1 qa/review-s1.jpg   # 拼成一张图看
node render.mjs clip 8 16                               # 连续片看节奏
node render.mjs full                                    # 整片（无声）→ out/video-silent.mp4
python ../scripts/mix_music.py --video out/video-silent.mp4 --music <曲目> --track <id> \
  --output out/final.mp4 --report out/mix.json --credit-out out/music-credit.txt   # 不传 --voice 就是纯音乐
```

1. **选题和数据**：从文章里找一个能算出来的数。写 `data/build_data.py`，所有上屏的数都从这里出，`qa/data-summary.json` 留给核对。随机数固定种子。
2. **分段写 `web/scene.js`**：每段 `add(t0, t1, draw)`，段内用 `head()` 打标题、`bigNumber()` 揭晓、`cells()` 画格子、`axes()` 和 `line()` 画曲线、`readout()` 画读数、`check()` 画清单。时间都写死在段里，主要的揭晓放在整秒上，方便对音乐。
3. **观感测试**：先出 15–20 张静帧拼成一张图，看字号、重叠、发光是否过亮；再渲一段 8 秒连续片看打字速度和淡入淡出。**用户在场就先给用户看。**
4. **整片和配乐**：渲无声整片，至少混两首曲子给用户听。配乐做法见[声音与素材](audio-and-materials.md)。
5. **交付**：`final.mp4`、无声版、数据摘要、来源、配乐署名和分镜总览。

## 质量底线

- 每个数字都能在 `data-summary.json` 里找到，文字和画面不手抄数字。
- 每屏都有东西在动：打字、格子翻开、曲线生长、计数器跑。连续 3 秒以上全静止就要改。
- 金色只给关键的词和数，满屏金色等于没有重点。发光宁弱勿强，格子太亮会变成柠檬黄。
- 小字也要在手机上看得清：读数不小于 34px，坐标轴不小于 23px。
- 来源和“不构成投资建议”写在片尾或出处小字里。用了第三方实验或研究，要写清作者和年份。

## 实测踩过的坑

- 发光层叠加太多，金色格子发白发黄，不像参考片的橙金色。两层模糊的强度分别压到 0.38 和 0.32，格子自身发光 0.28。
- 曲线末端的百分比标签挤在一起。按纵坐标排序后至少错开 26px。
- 片名卡上的路径穿过标题，读不清。路径压到标题下方。
- Georgia 的数字是老式数字（3、9 会下沉），大数字用思源宋体 / Noto Serif SC 900。
