# 生产规范

## 固定什么

竖屏视觉锁文件：本 Skill 的 `assets/style-lock.json`。字幕按实际字符宽度排版，连续报数检查标点占位。横屏章节使用 `assets/chapter-style-lock.json`，不能机械照搬竖屏坐标。中文正文、标题与数字各有固定字体角色；同一影片保持一个主色系统，不随章节切换艺术风格。

复用工具分工：weilanx的Remotion组织与xilo的对象状态、实际渲染复核方法是既有参考。第一批明确标注的上游组件及OFL字体随仓库分发，其他参考只保存链接；实际范围见NOTICE.md。不同风格参考进入研究库，不自动混入生产主题。

## 不固定什么

不把不同原文硬塞进同一九个场景。先由问题决定解释动作，再用同一组件外观呈现。每个主结论必须能指向画面上的一个动作或可读证据；开头尽早给冲突和问题，解释段保留必要阅读时间。

动作规格至少含：`objectId`、`before`、`after`、`cue`、`entry`、`exit`、`nextObject`、`numericInvariant`、`verificationTime`。价格涨跌、回购分母、费用累计应由同一数据源驱动画面和文字，禁止单独手写一个动画数字。

## 内部检查如何替代用户反复评判

技术检查由代码做：规格、码率、帧数、解码、音轨、时间边界、字幕长度、数学不变量、素材缺失、字体与源码标记。检查脚本不能判断美。

内容和画面由 Agent 对最终实际帧做独立审查，能使用另一审查 Agent 时不把作者自评当独立结论。报告必须列时间码和观察到的证据，不只给8分、9分。重点检查：
- 不看字幕能否辨认主要对象在比较什么、怎样变化。
- 过渡是否保留对象、轮廓、方向或空间中的至少一种联系。
- 文字和数值是否在落稳后可读，进出场是否覆盖了另一段信息。
- 长时间不变是否确实用于阅读；装饰抖动不算解释推进。
- 数字、取整、参考点、平均值与单位是否一致。

修复路由：字幕越界只重排字幕；数字问题改共享数据；节奏问题先删重复口播或延长必要读数，不全片加速；连贯性问题重写交接动作；构图问题改组件布局。保留一次修复前后同时间码对照。已通过的语音和素材不重复请求。

## 验证流水线，而不是只验证一个视频

先在限定内容域做三类留出文章：概念解释、数字机制、事件复盘。每篇独立输入，不能复制上一条专用镜头当万能模板。记录：首遍硬错误数、内部修复轮数、人工干预数、总用时、服务请求、费用和源码改动范围。三篇都能在约定范围内交付，才称该范围跑通。

任务短片保留用户所需的可编辑交付。XML可解析不证明Premiere已打开。用户明确已手动验证且免除重复验证时记录其原话与范围，不再重复操作；未获此确认时如实报告缺口。Remotion源码、渲染素材、交换XML和原生工程分别标明，短片、三分钟扩展版、章节验证分别记录。
